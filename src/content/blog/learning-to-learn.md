## 从一个小问题开始

刚接触一个研究方向时，很容易被长长的学习清单包围。基础课程、论文、代码、工具，每一项似乎都很重要。

这份示例规划选择一个更具体的起点：**今天遇到的这个问题，我能不能用自己的话说清楚？**

记录不需要从一篇完整的教程开始。一个概念的解释，一次报错的分析，或者一段尚未想明白的推导，都可以成为第一篇文章。

## 给学习安排一个循环

可以尝试以两周为单位安排一个小循环：

1. 选择一个明确的问题，并列出需要的基础知识。
2. 阅读相关材料，记录自己的理解和疑问。
3. 用代码或一个小实验检验理解。
4. 整理结果，写下下一次想继续探索的方向。

> 写下来并不是为了证明“已经学会”，而是为了看清“还有哪里没懂”。

## 一张简单的复盘表

| 记录项 | 可以问自己的问题 |
| --- | --- |
| 本周收获 | 我能独立解释哪个概念了？ |
| 当前困难 | 问题出在知识、代码，还是实验设计？ |
| 下周目标 | 最值得推进的一件事是什么？ |

不用把每个小时都安排得满满当当。留下空白，才有空间重新思考。

## 让笔记慢慢生长

先保存一份粗糙的理解，再随着阅读和实践补充它。对旧文章的修订，也是学习的一部分。

这篇文章只是一份写作示例。你可以把它替换成自己的研一学习计划，也可以直接删除，开始写第一篇属于自己的记录。
