## 1. 先把研究问题说清楚：模型到底要预测什么

计算机视觉让计算机从图像中提取信息。分类回答“是什么”，检测回答“在哪里”，分割回答“哪些像素属于它”，质量评价回答“在约定的观看条件下，人会怎样评价这张图”。我的研究主线是**感知质量评价与数据库建设**；学习分类、检测和分割，则有助于我理解视觉模型和局部问题。

我先用一个最简单的无参考任务整理输入与输出：

$$
\hat q = f_{\theta}(I).
$$

$I$ 是一张待评价的全景图片，$f_{\theta}$ 是参数为 $\theta$ 的模型，$\hat q$ 是预测质量。训练时用真实主观标签帮助模型学习；推理时只给图片，不给完整高质量参考图。“无参考”描述可用参考信息，**不等于不需要标签，也不等于无监督学习**。

为了明确自己的评价目标，我需要区分四种可以研究、但不能直接混为一谈的判断：

| 判断 | 入门例子 | 对课题的意义 |
| --- | --- | --- |
| 技术画质 | 边缘是否模糊，阴影是否有噪声，压缩是否留下块状伪影 | UGC 与 AIGC 都可能存在 |
| 自然性／结构合理性 | 一把椅子很清楚，但椅腿连接关系不合理 | 仅靠清晰度难以解释生成错误 |
| 图文一致性 | 提示词要求海边，结果生成了森林 | 需要真实可用的提示词及单独任务定义 |
| 整体偏好／美感 | 两张图画质相近，但构图和风格带来不同偏好 | 不能自动当作技术画质的同义词 |

以“AI 生成的餐厅全景”为例：文字可能清晰却不可读，桌椅可能锐利却结构错误，ERP 接缝还可能把墙面断开。因此，我需要在评分问题中说明观察者究竟评价什么；是否另设自然性、空间合理性等维度，还要与导师讨论，并通过主观预实验确定。

**我的学习目标：** 用一页说明样本范围、标签含义、输入信息和输出目标，并解释为什么 AIGC／UGC 是来源变量，而不能直接作为好坏标签。

## 3. 数学与信号基础：只补当前真正用得上的部分

### 3.1 线性代数：理解数据形状和特征变换

标量是一个数，例如一张图的 MOS；向量是一列特征；矩阵可以表示灰度图片或一组特征；张量是更一般的多维数组。**张量的维度顺序比“它有几维”更重要**：`[H, W, C]` 和 `[C, H, W]` 都是三维，但通道位置不同。

线性层可以写作 $z=Wx+b$：输入向量 $x$ 被权重矩阵 $W$ 映射到另一种特征空间，再加偏置 $b$。我需要先补矩阵乘法的维度匹配、转置、范数、点积和余弦相似度，才能理解线性层、注意力、特征归一化和图文特征比较中的相应操作。

**我准备做的练习：** 手算一个二维向量乘矩阵，在代码里逐层打印 shape，并检查自己能否区分“特征长度”“批次数量”和“类别数量”。

### 3.2 导数与链式法则：理解学习为什么会发生

导数描述一个量微小变化时，另一个量如何变化。梯度是损失对多个参数的偏导数集合。反向传播利用链式法则，把最终误差沿计算图传回参数；优化器再决定如何更新它们。

最基本的梯度下降可写作：

$$
\theta_{t+1}=\theta_t-\eta\nabla_{\theta}\mathcal L.
$$

$\eta$ 是学习率，$\mathcal L$ 是损失。减号表示朝局部降低损失的方向走，不保证每一步都让验证结果变好。比如模型预测 70、标签 80，平方误差对这个预测值的导数为 $2(70-80)=-20$，更新会倾向提高预测；网络内部还要继续通过链式法则计算参数梯度。这里的数字仅为数学示例。

### 3.3 概率与统计：理解分数、误差和不确定性

均值描述中心，方差描述离散，相关性描述两个变量如何共同变化。主观评分不是没有噪声的物理测量：同一个人可能重复评分不一致，不同人也可能有不同感知。

我还需要理解抽样、标准差、置信区间、相关与因果的区别，才能判断“分数提高了”是否可能来自划分波动或样本构成变化。多个视口属于同一全景、多个生成版本属于同一内容家族，不能把它们当成完全独立样本来夸大有效样本量。

### 3.4 信号处理与球面几何：电子信息背景的连接点

采样把连续场景记录成离散像素；分辨率限制可以保留的细节；模糊会减弱高频信息；噪声会引入不属于场景的变化。**高频多不等于画质好**，噪声和过锐化也可能制造高频。

缩小图片前通常需要考虑低通／抗混叠，插值方式也会改变细节。接下来，我需要补经纬度、弧度、三维方向向量和旋转，这是正确提取 VR 视口的前提。

**我的阶段目标：** 能解释 shape、一次平方误差梯度、MOS 的均值与离散程度，以及缩图为什么可能抹掉噪声或细小伪影。

## 4. 数字图像与计算机视觉：先知道输入到底发生了什么

一张 RGB 图通常包含三个颜色通道。读图时，我需要核对 RGB／BGR 顺序、整数／浮点类型、取值范围、方向元数据和颜色空间。相同文件经过不同解码、resize 或 normalization，模型收到的数值不一定相同。

这里有两个名字相似、用途不同的步骤：

- **输入标准化**：例如先把 0–255 转为 0–1，再按预训练模型规定的均值和标准差处理。实际使用时，我需要遵循所用权重的预处理配置。
- **网络归一化层**：例如 BatchNorm、LayerNorm，处理的是网络内部激活，不是在替代读图和输入预处理。

预处理会影响质量标签的适用性。一张原始高清全景被大幅缩小时，压缩块、噪声和接缝可能不再显著。模型究竟预测原始展示下的质量，还是缩图展示下的质量？若标签来自前者，预处理就应尽量保留相关信息，并记录其影响。

**分类与 IQA 的数据增强也有差异。** 分类中加模糊可能仍保留“猫”这一类别；IQA 中加模糊可能改变质量，不能继续无条件使用原 MOS。随机裁剪也可能恰好躲开缺陷。选择每一种增强时，我都需要回答“它是否保留当前标签的含义”。

**我准备做的练习：** 把同一张图以原尺寸和两种较小尺寸展示，观察细节，保存读图前后 shape、范围与预处理配置。我希望借此发现信息损失；这些观察还不能代替主观实验。

### 5.2 Dataset 与 DataLoader 各做什么

`Dataset` 定义“取一个样本返回什么”；`DataLoader` 负责把样本组成批次，并管理顺序和加载。设计 Dataset 时，我考虑让一个样本返回全景 ID、视口集合、标签和必要元数据。来源字段用于分层评测，是否作为模型输入必须另行定义。实现入口可参考 [PyTorch 数据加载教程](https://docs.pytorch.org/tutorials/beginner/basics/data_tutorial.html)。

例如一个多视口批次的数据流是：

```text
全景图片 I
  → 固定球面采样得到 K 个视口
  → 单张数据 [K, 3, H, W]
  → 批次数据 [B, K, 3, H, W]
  → 视觉编码器输入 [B*K, 3, H, W]
  → 视口特征 [B, K, D]
  → 聚合得到整图特征 [B, D]
  → 回归头输出 [B]
  → 与整图标签 [B] 比较
```

`B` 是全景图片的批次数量，`K` 是每张图的视口数，`D` 是特征长度，`H/W` 是视口尺寸。这里是设计示意，不是指定某篇论文的真实实现；某些编码器输出 token 序列，还需要明确取哪种特征。

### 5.3 我需要区分的运行模式与梯度模式

`model.train()`／`model.eval()` 改变部分层的行为；`torch.no_grad()` 关闭梯度记录。**eval 不自动关闭梯度，no_grad 也不自动切换评估模式。** 测试时通常需要同时做好这两件事。[自动求导教程](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)

冻结编码器时，参数不更新还不够：若含 BatchNorm，训练模式下统计量仍可能变化。第一版练习中，我考虑把冻结编码器保持在 eval、只训练回归头，并核对整个模型调用 train 后是否把编码器重新切回训练模式。缓存冻结特征也能简化第一轮实验，但缓存要关联图片、视口、权重和预处理版本。

**我的练习目标：** 自己实现数据读取，画出上面的 shape 流，并检查标签和输出是否一一对应。我尤其需要排查 `[B, 1]` 的预测和 `[B]` 的标签意外广播成 `[B, B]` 的错误，不能只看程序是否运行。

## 6. 深度学习训练：逐个理解导师列出的术语

### 6.1 forward、loss、backward、step 是一个闭环

forward 根据图片计算预测；loss 衡量预测与监督的差距；backward 计算梯度；optimizer.step 根据梯度更新参数。常规训练还需要在每次迭代清空旧梯度，避免无意累积。[PyTorch 优化教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)

连续 MOS 回归的一个起点是均方误差：

$$
\mathcal L_{\mathrm{MSE}}=\frac{1}{B}\sum_{i=1}^{B}(\hat q_i-q_i)^2.
$$

$q_i$ 为标签，$\hat q_i$ 为预测。MSE 强调数值接近，ranking loss 强调成对顺序；cross entropy 通常对应类别／概率目标，例如离散质量等级。它们不能只因名字熟悉就替换：标签格式、输出层和任务定义要一起匹配。

我把一次训练的基本过程整理如下。**实际练习时，我仍需实现 model、train_loader、optimizer，并使用真实标签；这段框架尚不构成完整的全景 IQA 项目**：

```python
model.train()
for images, mos in train_loader:
    optimizer.zero_grad()
    prediction = model(images).reshape(-1)
    target = mos.to(prediction.device, dtype=prediction.dtype).reshape(-1)
    assert prediction.shape == target.shape
    loss = ((prediction - target) ** 2).mean()
    loss.backward()
    optimizer.step()
```

这里还假设 `images` 已在正确设备上，冻结模块的模式已按上一节处理。我准备先在少量训练样本上检查形状、梯度和损失是否可下降；“能记住训练样本”只是一项程序诊断，不是泛化证明。

### 6.2 优化与训练控制

| 术语 | 直观理解 | 我的第一版实验需要关注 |
| --- | --- | --- |
| SGD | 按当前批次梯度更新参数 | 学习率和批次波动 |
| Momentum | 累积更新方向，减轻来回摆动 | 不等于直接把学习率加大 |
| Adam | 利用梯度一阶／二阶统计调整更新 | 对不同参数作自适应调整，仍需调学习率 |
| AdamW | 将权重衰减与自适应梯度更新分开处理 | 衰减强度及哪些参数参与衰减 |
| Learning rate | 每次更新的步幅 | 太大可能不稳定，太小可能进展缓慢 |
| Warmup | 开始时逐步升高学习率 | 一种稳定训练策略，不是必选仪式 |
| Cosine scheduler | 按余弦曲线调整学习率 | 总步数、最低学习率和恢复训练的位置 |
| Batch size | 一次用于更新的样本数 | 多视口时区分 B 张全景与 B×K 个视口 |
| Epoch | 通常表示完成一轮训练数据遍历 | 与 iteration、optimizer step 区分 |

我不能把一个“大模型常用学习率”直接当作适合本课题的结论。我计划先固定一套基线配置，再利用验证集调整；测试集不参与挑选学习率、训练轮数或最优 checkpoint。

### 6.3 归一化、正则化与泛化

**BatchNorm** 通常利用批次与空间位置统计各通道激活，并在默认设置下维护推理用的运行统计；**LayerNorm** 在每个样本的指定特征维度上归一化。它们不是“前者用于 CNN、后者只能用于 Transformer”的硬性规则。小批次和训练／测试分布变化可能影响 BatchNorm，应结合实现检查。[BatchNorm 文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.BatchNorm2d.html)、[LayerNorm 文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.LayerNorm.html)

Dropout 在训练中随机屏蔽部分激活，weight decay 对参数大小施加约束。它们都用于控制模型的拟合方式，但机制不同。**过拟合**表现为训练效果好、未见内容效果差；**欠拟合**可能在训练数据上也学不好。还要排查标签方向错误、预处理不匹配和代码问题，不能把所有低指标都归因于网络不够大。

**预训练**让模型先从其他数据学表示，**微调**让部分或全部参数适应当前任务。我的第一版练习考虑冻结 backbone、训练轻量回归头，之后再比较逐层解冻或微调。预训练模型仍可能带来分布偏差，强特征不等于已经解决质量评价。

**我的学习目标：** 解释每个配置项的作用，学会保存并恢复模型、优化器、调度器和进度。我也需要理解，保存随机状态有助于续跑一致性，但不保证跨设备完全逐位一致。

## 7. CNN、ResNet 与 Transformer：理解特征如何产生

### 7.1 卷积和 ResNet

卷积让同一组可学习滤波器在不同位置提取模式。浅层常关注边缘和局部纹理，经过多层和下采样，网络可组合更大范围的信息。感受野表示一个特征受到输入哪些位置影响；CNN 并非只能处理局部，只是局部连接与层级结构带来特定归纳偏置。

ResNet 使用残差连接，例如 $y=x+F(x)$；形状不匹配时需要相应投影。它让模块学习对已有表示的修正，有助于深层网络优化。阅读模型代码时，我需要观察输出通道数、下采样比例和池化方式，而不只记住网络层数。

与 IQA 的联系：局部模糊、压缩纹理和生成伪影可能体现于局部特征；整图内容又影响人如何注意和判断。若过早平均池化，局部严重缺陷可能被冲淡。因此“局部信息怎么汇总”本身就是研究问题。

### 7.2 Patch、Token 与注意力

ViT 把图片划成 patch，经投影形成 token，再通过注意力交换信息；patch 是图像区域，token 是其向量表示。位置编码提供空间位置信息。Swin 使用窗口及移位窗口等机制组织交互；入门阶段，我先关注其层级和交互范围。

自注意力的一种常见形式是：

$$
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}\right)V.
$$

Query 可以理解为当前 token 的“查询”，Key 用于匹配，Value 是被汇集的信息；三者通常由输入经学习到的投影产生。softmax 把相似度转成权重，$d_k$ 是 Key 的维度。多头注意力让多个投影子空间并行建模关系；注意力权重不自动等同于人眼显著性或质量解释。[Transformer 原论文](https://arxiv.org/abs/1706.03762)、[ViT 原论文](https://arxiv.org/abs/2010.11929)

| 模型视角 | 我要理解的优势 | 用于质量评价时需要检查 |
| --- | --- | --- |
| CNN／ResNet | 局部连接、共享滤波器、层级特征 | 下采样是否丢掉细小伪影 |
| ViT | token 间关系与内容交互 | patch 尺寸、位置、分辨率和计算成本 |
| Swin／多尺度方法 | 局部窗口与跨尺度表示 | 局部失真和整体语义如何结合 |

**我准备做的练习：** 对一张正常图和一张局部模糊图，观察相同模型的特征或输出差异；更换输入尺寸时，检查预处理和位置编码。可视化特征仅帮助排查，不足以证明模型正确理解了质量。

## 8. CLIP、DINO、SigLIP 与 VLM：预训练能给我什么

对照导师 §4.3，我需要理解这些模型提供了什么特征，以及为什么可能帮助 IQA。首先需要区分**视觉特征**、**图文对齐**和**可以生成语言描述的多模态模型**。

| 入口 | 基本思想 | 在当前课题里的学习用途 |
| --- | --- | --- |
| CLIP | 通过图文配对学习图像与文本表示 | 比较图片与质量描述的相似性，或使用图像特征 |
| DINO／DINOv2 | 从图像自监督学习视觉表示 | 用冻结特征建立回归基线；不把它当作原生文本模型 |
| SigLIP | 图文预训练中使用成对 sigmoid 损失 | 理解另一类图文特征；检查所选权重与预处理 |
| VLM／MLLM | 视觉语言／多模态模型的不同实现 | 研究质量描述、局部问题与评分，明确实际输入输出 |

对应原始资料：[CLIP](https://arxiv.org/abs/2103.00020)、[DINOv2](https://arxiv.org/abs/2304.07193)、[SigLIP](https://arxiv.org/abs/2303.15343)。我把它们作为理解表示学习的入口，具体哪类特征更适合拟建立的混合全景数据库，还需要通过实验判断。

**图文相似度不是主观画质的真值。** 某张图很符合“餐厅”描述，仍可能模糊或桌椅结构错误。使用质量文本提示的 [CLIP-IQA](https://arxiv.org/abs/2207.12396)可以作为原论文学习入口；将其用于全景视口并聚合，是需要验证的任务迁移。

导师 §10 中的 LoRA 是通过低秩增量等方式适配部分权重，属于参数高效微调路线。它降低需要训练的参数量，不自动消除标签需求，也不保证总显存一定很小。质量等级离散化会损失一些连续分数信息；选择连续回归还是等级学习，应对应标签和实验目标。

模型生成“这里有压缩伪影”这类文字时，我需要检查图中是否真有证据。若加入提示词、参考图、真实头动或眼动，输入条件已经改变，应与纯图片 NR 基线分开报告。使用人类质量标签适配后的模型也不能继续当作未经适配的零样本结果。

**我的学习目标：** 说明所用模型的监督来源、输入、特征、输出及预处理，并区分冻结提特征、零样本打分和用 MOS 微调这几种基线。

### 8.1 生成模型基础：为什么需要记录生成过程

我的课题涉及生成内容的质量评价，因此我需要先理解“图片怎样产生”。入门阶段，我准备先弄清生成过程与元数据，再判断是否需要进一步训练生成器。文本生成图像（T2I）主要由文字条件引导，图像生成／编辑图像（I2I）还依赖输入图；扩图、修复则需要关注哪些区域保留、哪些区域被生成。实际工具可能组合多种过程。

以扩散路线为例，训练可以通过对数据加噪、学习相应去噪目标建立生成模型；采样通过一系列更新逐步产生图像，不是简单把一张现成模糊图“修清楚”。潜空间扩散把主要生成过程放到编码后的表示空间，再由解码器还原图像，并可使用文字等条件。[DDPM 原论文](https://arxiv.org/abs/2006.11239)、[潜空间扩散原论文](https://arxiv.org/abs/2112.10752)

这也是我需要记录模型版本、提示词、随机种子、采样参数、条件图和后处理的原因：它们可能改变图片内容和伪影。相同 seed 不保证跨模型、配置和设备得到相同图；推理去噪步骤也不是质量模型的训练 epoch。普通生成器输出一张 2:1 图，并不自动保证球面接缝、极区和空间关系正确。

## 9. IQA 基础：参考图、失真、主观标签与传统指标

### 9.1 FR、RR、NR 的区别

FR 使用完整参考图；RR 使用来自参考图的部分信息；NR 不依赖这些参考信息。AI 生成图片的提示词不是像素级参考；AI 编辑图片的条件图也不一定可直接作为对应画面的无失真真值。

还要区分失真来源：人工加噪等属于合成失真；真实拍摄／上传过程可能混合多种失真；生成内容可能出现结构、纹理和空间错误；增强、修复和锐化也可能产生新伪影。它们可以共存，并非按来源互斥的几个标签。

### 9.2 MOS、DMOS 与主观实验

MOS 是在规定协议和必要处理之后，对有效主观评分求均值的一种标签：

$$
\operatorname{MOS}_i=\frac{1}{M_i}\sum_{j=1}^{M_i}s_{ij}.
$$

$s_{ij}$ 表示第 $j$ 个有效观察者对第 $i$ 张图的评分，$M_i$ 是该图片的有效评分数量。实际数据库可能还做观察者筛选、评分归一化或其他处理，必须阅读其说明。均值相同的两张图也可能有不同评分方差。

DMOS 与参考相比表达质量差异，但具体计算方式和高低方向由数据库定义。使用数据时，我需要先核对分数方向和范围，不能机械地认定所有 MOS 都越大越好、所有 DMOS 都使用同一范围。绝对等级评分让人分别打分，成对偏好让人比较两张图；成对偏好不能不经建模就冒充 MOS。

VR 主观实验还要固定设备、视口、起始朝向、浏览时间或自由浏览规则、评分问题、顺序随机化和休息安排。若使用普通屏幕模拟观看，我需要准确记录显示条件；舒适度与整体 QoE 还受设备、交互等因素影响，不能仅凭一张图片分数声称已测完整沉浸体验。

### 9.3 传统指标应该怎样使用

| 方法 | 需要参考吗 | 它主要提供什么信息 | 当前课题里的边界 |
| --- | --- | --- | --- |
| PSNR | 完整参考 | 基于像素均方误差的信号保真度 | 需明确配准、动态范围及通道；不能代表所有感知问题 |
| SSIM／MS-SSIM | 完整参考 | 局部结构等相似性，后者结合多尺度 | 必须有可比较的参考，不自动处理生成语义错误 |
| LPIPS | 完整参考 | 学习特征上的感知距离 | 是距离而非直接 MOS，仍依赖参考条件 |
| NIQE | 无参考 | 与建模的自然图像统计分布的偏离 | 生成内容、球面投影可能不满足其适用假设 |
| BRISQUE | 无参考 | 基于自然场景统计特征的学习型评价 | 训练／测试分布变化会影响迁移表现 |

它们是可解释的工具和对照，不是质量标签的自动替代品。需要参考的指标只在确有参考的子任务里使用；普通二维 NR 指标用在 ERP 或视口上，也要明示适配方式。更多方法与综述原文定位见[阅读报告](../iqa-vqa-360-reading-report/)。

## 10. VR／360° 前置知识：图片坐标不等于球面观看

### 10.1 ERP 和球面表示

ERP（等距柱状投影）把经度和纬度映射到平面，完整球面常以 2:1 的宽高比保存。但 **2:1 只是检查线索，不能证明图片真的覆盖完整球面，也不能证明几何连续**。我需要核查上下覆盖、左右接缝、极区与元数据。

在一种常用约定中，像素中心 $(u,v)$、宽高 $(W,H)$ 对应：

$$
\lambda=2\pi\left(\frac{u+0.5}{W}-\frac12\right),\qquad
\varphi=\pi\left(\frac12-\frac{v+0.5}{H}\right).
$$

$\lambda$ 为经度，$\varphi$ 为纬度，范围约为 $[-\pi,\pi)$ 和 $[-\pi/2,\pi/2]$。这里规定图像上方是北极方向；不同工具的坐标轴、正方向和起始朝向可能不同，不能只复制公式而不验证。

ERP 同样大小的像素对应的球面面积随纬度变化；面积因素与 $\cos\varphi$ 有关。平面等权平均会相对强调极区。面积修正解决几何计数问题，**并不等于真实观看概率或人眼显著性权重**。

### 10.2 视口、FOV 和接缝

视口是给定朝向和视场角下可见的一块画面，常用透视投影模拟。yaw、pitch、roll 描述朝向；FOV 描述视场角，水平 FOV、垂直 FOV 和输出宽高比之间需要一致。视口提取要从输出像素构造三维射线、按朝向旋转，再映射回 ERP 并插值采样；不是把 ERP 上一个矩形直接裁下来。

经度左右边界在球面上相邻，采样时通常需要水平环绕处理；两极附近不能把纬度越界简单当作普通上下环绕。练习时，我准备用带方向标记的测试图检查前、后、左、右、上、下，再检查跨经度接缝的视口是否连续。

### 10.3 多视口聚合与观看行为

一个最小、待验证的特征聚合基线可以写为：

$$
\hat q=g\!\left(\sum_{k=1}^{K}a_k\,h(V_k)\right),\qquad
a_k\geq0,\quad\sum_{k=1}^{K}a_k=1.
$$

$V_k$ 是视口，$h$ 提取特征，$a_k$ 是聚合权重，$g$ 输出整图质量。平均聚合取 $a_k=1/K$。这是一种入门设计，不证明它优于其他方法，也不保证可以捕捉面积很小的严重错误。

平面均匀网格、球面近似等面积采样、基于显著性的采样和按浏览序列采样并不相同。固定采样便于建立可复查基线；真实 head movement 是头部朝向变化，scanpath 还需明确是视口序列还是眼动轨迹。采样策略是否贴近用户观看，需要证据。

静态全景存在浏览顺序，但源图片本身没有视频帧间运动。[Assessor360](https://arxiv.org/abs/2305.10983)通过伪视口序列研究全景浏览建模，是后续精读入口；不能把它自动理解为需要真实眼动，或认为其结论已经验证了 AIGC／UGC 混合全景。

**我的学习目标：** 从同一 ERP 提取并可视化不同朝向的视口，说明坐标、FOV、尺寸、插值和环绕，并解释面积权重、采样概率与质量聚合权重之间的区别。

## 11. 混合数据库：来源、标签和内容关系都是基础知识

数据库不只是图片文件夹。它还需要样本范围、授权来源、元数据、主观协议、标签处理、内容关系和可复用的划分。我先整理一份待讨论、待实践的字段设计，**目前还没有据此建成数据库**：

| 字段组 | 我计划记录的内容 | 为什么重要 |
| --- | --- | --- |
| 标识与几何 | image_id、路径、尺寸、投影、哈希 | 识别文件、查重复、检查输入 |
| 来源与处理 | UGC／AIGC／AI 编辑、来源许可、处理链 | 解释来源构成及可发布范围 |
| 内容关系 | content_group_id、parent_id、条件图关系 | 同场景、派生版本和视口共同分组 |
| 生成信息 | 模型／版本、提示词、参数、seed；不可用则注明 | 复查生成流程与跨生成器评测 |
| 标签与协议 | 维度、原始评分、有效人数、MOS／离散程度、协议版本 | 知道分数怎么来，避免把不确定性藏起来 |
| 划分与实验 | split、划分版本、视口配置、数据版本 | 让结果可追溯并排除泄漏 |

同一实拍场景的不同失真版本、同一条件图的生成／修复结果、同一全景的所有视口，都要检查是否属于同一内容家族。同一提示词下是否应进一步分组，要结合实际相似度和评测目标确定；不能只依赖文件名不同。

来源和质量分布也要分析。如果 UGC 全是高清室外，AIGC 全是低清室内，模型可能学场景、分辨率或来源捷径。总体相关性高，未必说明在两类内部都能判断质量。因此，我计划检查各来源的内容、尺寸与分数分布，并分别报告 UGC、AIGC 和混合结果。

[AGIQA-3K](https://arxiv.org/abs/2306.04717)把生成图像的感知质量与图文一致性分别标注，可借鉴标签区分；它是普通生成图像数据库，不能直接代替我拟建立的混合全景数据库。新数据库的标签、协议与覆盖范围仍需独立设计。

**一个关键边界：整图 MOS 不是每个视口的真实质量。** 某张图整体得分低，可能只是接缝处有严重错误。若把这个分数复制给全部视口，会让正常区域也被赋低分。需要明确这是弱监督假设，或先聚合视口特征再对整图标签学习，不能声称已获得真实局部标注。

## 12. 评价指标与实验协议：为什么“数字更高”还不够

### 12.1 训练、验证、测试各负责什么

训练集用于更新参数；验证集用于选择配置、模型和 checkpoint；测试集用于对最终方案评估。**先按内容家族划分，再派生视口、裁剪和增强**，避免同一内容进入训练与测试。

视口采样、标签归一化、特征标准化、聚合设置、提示词模板和映射参数都可能成为被选择的配置。凡使用标签拟合的步骤，应在训练／验证阶段确定；不能反复看到测试结果后继续调整，又把最终结果当作一次独立测试。

### 12.2 SRCC、PLCC、KRCC、RMSE 分别看什么

| 指标 | 直观问题 | 解读边界 |
| --- | --- | --- |
| SRCC | 模型排序与人的排序是否一致？ | 看秩；并列分数需用正确实现处理 |
| PLCC | 预测与主观分数是否有线性相关？ | 高相关不等于数值误差小 |
| KRCC | 样本对之间的次序是否一致？ | 使用并说明具体版本及并列值处理 |
| RMSE | 数值误差平均有多大？ | 依赖标签尺度，跨数据库不能直接比大小 |

举一个说明：人的分数是 `[1, 2, 3]`，预测是 `[10, 20, 30]`，排序和线性关系完全一致，但原尺度 RMSE 并不小。这说明相关性、标定和绝对误差是不同问题；三张样本仅为数学演示，不是性能证据。

评测前，我需要统一分数高低方向，不能对相关系数取绝对值来掩盖反向预测。小样本、分数变化范围窄或预测几乎恒定，都可能让相关系数不稳定或无法定义。

Logistic mapping 是非线性分数标定方法。有些 IQA 论文按既定 benchmark 协议在评测集上做拟合后报告 PLCC／RMSE；复现时应明确标注为该协议下的 post-fit 结果，并与原始预测指标区分。面向可部署预测器时，标定参数在训练／验证集拟合，再固定到测试集；不能把使用测试标签完成的标定描述成完全独立的预测效果。

### 12.3 我准备如何落实导师 §5.5 的实验要求

导师原文明确要求内容隔离、记录种子与划分、尽量沿用已有工作划分、重要实验重复、保存预测、绘制散点图、分析失败，以及条件允许时跨数据库评测。结合自己的课题，我计划把这些要求落实为以下习惯：

1. 保存 content_group_id 和划分文件，检查两组没有内容家族重叠；同一全景视口保持在同一组。
2. 记录随机种子、代码提交、数据版本、权重和配置；重复次数与统计汇总方式提前确定。
3. 保存每张全景的 ID、来源、真值、预测和误差；散点图按来源区分，观察来源内部而非只看总体趋势。
4. 检查误差最大的图、接缝附近图和局部生成错误图；区分数据、标签、几何、模型和分布问题。
5. 跨来源、跨生成器或跨数据库测试前检查训练／测试重叠，且外部数据不能参与调参。
6. 做消融时尽量固定 backbone、预训练、数据划分与训练预算，每次改变一类因素。

多种随机划分的均值和波动，与固定官方划分上的单次结果不是同一个协议。引用别人结果时，我需要先核对数据、输入、预训练和评测条件；换了更大 backbone 或加入额外标签，不能把全部提升归因于自己的新模块。
